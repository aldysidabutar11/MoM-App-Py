# ===========================================================================
# MoM-IGD - Phase 1 RUNTIME dependencies, exact versions.
#
# Target interpreter: official Python 3.12 (python.org, per-user install).
# NOT the Microsoft Store shim, NOT Python 3.14.
#
# Install:
#     py -3.12 -m venv .venv
#     .venv\Scripts\python.exe -m pip install -r requirements.txt
#
# Refresh (after deliberately changing a direct dependency in pyproject.toml):
#     .venv\Scripts\python.exe -m pip install --upgrade <package>
#     .venv\Scripts\python.exe -m pip freeze --exclude-editable
#   then move dev-only lines into requirements-dev.txt and keep this file to the
#   runtime closure. `tests/test_offline_policy.py` fails if a cloud SDK or a
#   deferred AI/audio dependency appears in the environment, and
#   `tests/test_cli.py` fails if any line here is not pinned with `==`.
#
# Hash-pinned offline wheelhouse creation is deferred to Phase 11.
# ---------------------------------------------------------------------------
# DIRECT (9): fastapi, uvicorn, psutil, pywebview, sounddevice, cryptography,
#            faster-whisper, av, llama-cpp-python
# Everything else below is a transitive dependency of those nine.
#
# `sounddevice` arrived with Phase 2 (offline audio capture). It is the only
# audio dependency: it wraps PortAudio/WASAPI for input, and `RawInputStream`
# hands us raw bytes, so NumPy is not required. WAV files are written with the
# standard-library `wave` module and checksums with `hashlib`, so no codec,
# resampler or DSP library is needed either.
#
# `cryptography` arrived with Phase 3 (voiceprint encryption at rest). It supplies
# AES-256-GCM, which the standard library does not have. It is used for exactly
# that: authenticated encryption of biometric templates. Notes:
#   - the master key is protected by Windows DPAPI, reached through `ctypes` and
#     `crypt32.dll`, so pywin32 is NOT required for two API calls;
#   - the wheel is prebuilt (cp311-abi3-win_amd64), so no compiler is involved;
#   - it makes no network call, and nothing in this project asks it to;
#   - `cffi`/`pycparser` were already in the closure, so this adds exactly one
#     distribution.
# Base64 is NOT an alternative and must never be used as one (ADR-0010).
#
# `faster-whisper` and `av` arrived with Phase 4 (offline ASR), chosen by the
# Phase 4A benchmark (ADR-0014). Notes:
#   - `ctranslate2` is the CPU inference engine; INT8 is what the benchmark
#     selected, and the wheel is prebuilt so no compiler is involved;
#   - `onnxruntime` is required by faster-whisper for the Silero VAD model, which
#     ships INSIDE the faster-whisper wheel (`assets/silero_vad_v6.onnx`). The VAD
#     artefact is therefore local by construction and never downloaded. That build
#     also exposes an `AzureExecutionProvider`; the provider boundary pins
#     `CPUExecutionProvider` explicitly and a test asserts it;
#   - `av` gives FFmpeg decode + high-quality resampling for the 16 kHz mono
#     working copy. It is reused from this stack rather than adding a second audio
#     toolchain (soxr/librosa/soundfile all stay forbidden);
#   - `numpy` is a hard requirement of ctranslate2. The Phase 2 capture path still
#     does not use it -- `RawInputStream` yields bytes and the quality meter uses
#     `array.array` -- and that must not change;
#   - `huggingface-hub` is present because faster-whisper declares it. It is used
#     ONLY by the explicit `asr provision` command. A test asserts no runtime code
#     path imports it, and no model is ever fetched implicitly.
#
# `llama-cpp-python` arrived with minutes generation. Notes:
#   - it is NOT on PyPI for win_amd64. `pip install llama-cpp-python` reports
#     "from versions: none" and, with a source fallback, would demand MSVC. The line
#     below therefore pins the maintainer's own release wheel by **direct URL and
#     SHA-256**, so `pip install -r requirements.txt` works unchanged on a fresh clone.
#
#     A direct URL rather than `--extra-index-url`: an extra index applies to EVERY
#     package in the file, so a name-squatted build on that index could shadow a PyPI
#     package. Pinning one URL scopes the exposure to one artefact, and the hash means
#     even that artefact cannot change under us.
#
#     The hash was verified against the wheel actually tested on this machine. It is a
#     CPU-only build; never substitute a cuXXX variant, because the target GPU is an
#     Intel Iris Xe and there is no CUDA on the production device;
#   - it is chosen over the CTranslate2 stack already present because converting a
#     model for CTranslate2 needs `transformers` AND `torch`, both multi-gigabyte and
#     both still deferred. GGUF is distributed ready to run;
#   - it makes no network call. `assert_llm_offline_environment()` sets the offline
#     flags by assignment and deletes any inherited Hugging Face token;
#   - `diskcache` and `jinja2` are its declared dependencies. `jinja2` renders the
#     chat template that is embedded in the GGUF itself -- a local string, never a
#     fetched template.
#
# MODEL BINARIES ARE NOT DEPENDENCIES. They live under <data_root>/models,
# are provisioned by an explicit command, are hash-verified before promotion, and
# are never committed. A missing model fails closed as MODEL_UNAVAILABLE.
#
# Deliberately ABSENT and forbidden:
#   - any cloud SDK (google-genai, openai, anthropic, boto3, azure-*, ...)
#   - torch, pyannote.audio, speechbrain (Phase 5); transformers,
#     sentence-transformers (never needed: GGUF runs through llama.cpp, and either
#     one would pull torch in)
#   - openvino, optimum-intel, onnxruntime-openvino/-gpu/-directml: RULED OUT on
#     measured evidence, not merely deferred (ADR-0014)
#   - soundfile, librosa, pyaudio, soxr, webrtcvad, silero-vad
#   - Redis, Kafka, MinIO, any vector database
# ===========================================================================
